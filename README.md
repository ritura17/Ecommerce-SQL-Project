# E-Commerce SQL Analysis Project

A complete MySQL-based e-commerce database project designed to demonstrate
database design, SQL querying, data analysis, views, stored procedures,
triggers, indexing, and data-quality validation.

---

## Project Overview

This project simulates an e-commerce business database containing customers,
products, categories, orders, order items, payments, and shipping information.

The project focuses on using SQL to:

- Design a relational database
- Manage relationships between multiple tables
- Analyze sales and customer behavior
- Identify top-performing products and customers
- Analyze revenue by category
- Track orders and payments
- Monitor inventory
- Create reusable SQL views and stored procedures
- Automate database operations using triggers
- Improve query performance using indexes
- Perform data-quality and validation checks

---

## Business Objectives

The database is designed to answer real-world business questions such as:

- What is the total revenue?
- Which products sell the most?
- Which products generate the highest revenue?
- Who are the top customers?
- Which categories generate the most revenue?
- Which products have low inventory?
- How many orders are delivered?
- What payment methods are most commonly used?
- What is the average order value?
- Which customers have never placed an order?
- Which products have never been ordered?
- How does revenue change over time?

## Database Structure

The project contains the following main tables:

| Table | Description |
|---|---|
| `customers` | Stores customer information |
| `categories` | Stores product categories |
| `products` | Stores product information and inventory |
| `orders` | Stores customer orders |
| `order_items` | Stores products included in each order |
| `payments` | Stores payment information |
| `shipping` | Stores shipping information |

##  Advanced SQL Features

### Stored Procedures

Reusable procedures were created for tasks such as:

- Retrieving products
- Searching products
- Finding customer orders
- Finding low-stock products
- Filtering products by category
- Filtering orders by status

### Triggers

Triggers were implemented for inventory management, including:

- Automatically reducing stock after an order item is added
- Restoring stock when an order item is deleted
- Preventing negative inventory

### Indexes

Indexes were added to frequently searched columns to improve query performance.

Examples include:

- Customer email
- Order customer ID
- Order date
- Product category
- Product name

### Query Optimization

`EXPLAIN` was used to inspect query execution plans and understand index usage.

---

## Data Quality & Validation

The project includes SQL checks for:

- Duplicate customers
- Invalid product prices
- Negative inventory
- Invalid order quantities
- Invalid payment amounts
- Missing relationships
- NULL values
- Order-total mismatches
- Payment-total mismatches
